      22              : // multi_list is a data structure to maintain membership information for N elements in M sets.
      23              : // The items are always the numbers 0..N-1, intended to be used as indices into another data
      24              : // structure on the side (in case of shed, multiple other arrays)
      25              : //
      26              : // Invariants:
      27              : //  - The total number of items and also sets/buckets stays constant
      28              : //  - Every index is a member of exactly one set at all times
      29              : //
      30              : // Characteristics:
      31              : //  - Memory consumption is O(N + M)
      32              : //  - Iteration of members of any set is O(Nx), with Nx being the number of elements in the given
      33              : //    set
      34              : //  - Iteration of members not in a set is O(N)
      35              : //  - Transferring of any number of elements from set A to set B is O(Na)
      36              : //  - Operations on empty sets are always O(1)
      37              : //  - All operations use sequential memory access patterns with high locality
      38              : //  - All operations are done in place and don't require extra memory
      39              : //
      40              : // Implementation:
      41              : //  The idea is to use M linked lists interleaved inside one shared array.
      42              : //  By using indices instead of pointers a smaller type (uint16_t) than pointer size can be used
      43              : //  to save memory and increase locality.
      44              : //  To make set transfers faster, the lists are doubly-linked, with the backwards links stored
      45              : //  in a separate array on the side to make forward iteration faster by not polluting the cpu cache
      46              : //  with backward links not needed for forward iteration.
      47              : //  The index of any element serves as it's address, but also as it's associated value/"payload"
      48              : //  Therefore no extra memory for "payload" is required.
