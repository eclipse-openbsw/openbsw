# Release Notes

## [2027-01]

### Added

### Changed

* Middleware: `send()` now broadcasts the currently stored skeleton attribute
  value without changing it. Call `set(value)` separately before sending a
  new value; the argument-taking `send(value)` overload has been removed. This
  separates local attribute updates from broadcast success: applications may want
  to update the value only after a successful send (and retain or restore the
  previous value on failure), or update it regardless so that subsequent getter
  requests return the latest value. A broadcast is considered failed if at
  least one client cluster fails to receive it.
* Middleware: generated `SkeletonBase` subclasses now use distinct
  response methods for each method and attribute, avoiding duplicate
  definitions when operations have matching signatures:
  * Method responses are named `respond<MethodName>(...)`.
  * Attribute getter/setter responses are named
    `respondGet<AttributeName>Attribute(...)` and
    `respondSet<AttributeName>Attribute(...)`.
  * Attribute accessors `get_<AttributeName>Attribute(...)` and
    `set_<AttributeName>Attribute(...)` are now
    `get<AttributeName>Attribute(...)` and `set<AttributeName>Attribute(...)`.
  * Cancellation APIs `cancelGet_<AttributeName>AttributeResponse(...)` and
    `cancelSet_<AttributeName>AttributeResponse(...)` are now
    `cancelGet<AttributeName>AttributeResponse(...)` and
    `cancelSet<AttributeName>AttributeResponse(...)`.
  * For `setAsMethod` attributes,
    `respondSet<AttributeName>Attribute(response, bool result, handleResponseFailure = true)`
    now responds with a success flag instead of echoing the attribute value.
* Middleware: method and getter payloads are now returned by const
  reference. Request/response method and getter callbacks receive
  `etl::expected<etl::reference_wrapper<PayloadType const>, Future::State>`
  instead of `etl::expected<PayloadType, Future::State>`; access the payload
  through `output.value().get()`. Generated proxies expose a
  `<MethodName>Result` alias, and `ProxyAttributeBase` / `ProxyAttribute` expose
  `GetterResult` / `RequestResult` aliases for these callback result types.
* Middleware proxy API updates:
  * `invalidateFuture(Future future)` was replaced by
    `cancelGetterRequest(uint16_t reqId)` or
    `cancelSetterRequest(uint16_t reqId)` for attributes, and
    `cancelRequest(uint16_t reqId)` for methods.
  * Future objects are no longer the application's responsibility.
  * `setResult(Message msg)` was replaced by `answerGetterRequest(Message msg)`
    or `answerSetterRequest(Message msg)` for attributes, and
    `answerRequest(Message msg)` for methods. The method response path now uses
    `futureMatchingRequestId(msg)` instead of `releaseRequestId(msg)`.
  * Attribute `get(Callback& callback)` now takes a `GetterPolicy::Callback`
    as input and returns `etl::expected<uint16_t, HRESULT>`.
  * Attribute `set(ArgType& payload, Callback& callback)` now takes a callback
    and returns `etl::expected<uint16_t, HRESULT>`. For Fire&Forget setters,
    `set(ArgType& payload)` takes no callback and returns
    `INVALID_REQUEST_ID`.
  * Method calls now take a callback instead of a future and return
    `etl::expected<uint16_t, HRESULT>`.
* Middleware generator updates:
  * `<InterfaceName>Proxy.h` no longer creates aliases for attribute classes;
    only the constructor needs to be generated.
  * `<InterfaceName>Proxy.cpp` no longer generates
    `*_releaseRequestId(...)` methods; dispatcher methods are called directly
    from `OnNewMessageReceived`. Method bodies also include updated return
    statements and additional checks.
  * `<InterfaceName>Skeleton.h` generates a
    `cancel<MethodName>Response(SkeletonResponseInfo response)` method for
    each method.
